# T9.1 — Actionable Ollama integration

## Objective

When a user verifies selected content, Mark Tini should keep the OpenAlex source lookup working online, automatically start an existing Ollama installation where possible, use a sensible Vietnamese-capable default model, and show exact setup actions when local AI is unavailable.

## File-Level Plan

- Backend: default to `qwen2.5:3b`; report the model name and a stable local-AI status without turning Ollama failures into API failures.
- Electron: expose only `ensureOllama`, check the local API, and start the known per-user Windows executable when present.
- Renderer: call `ensureOllama` before verification and replace the dead-end message with an explicit OpenAlex/Ollama explanation, official install link, model name, and copyable pull command.
- Tests/docs: cover success, unreachable service, and missing model; document size/optional-companion rationale.

## Best Practices

- Keep renderer sandboxed and avoid generic command execution.
- Do not fail OpenAlex lookup when optional Ollama is unavailable.
- Preserve environment-variable overrides for advanced users.
- Keep all user-facing setup text in Vietnamese and actionable.
