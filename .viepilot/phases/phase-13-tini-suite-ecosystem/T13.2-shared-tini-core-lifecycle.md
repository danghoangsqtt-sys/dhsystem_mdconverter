# T13.2 — Shared Tini Core Lifecycle

## Objective

Cho hai product dùng chung đúng một FastAPI backend và một bộ lập lịch tài nguyên, có khả năng tự phục hồi và tự thoát an toàn.

## Work

- Xây dựng Core supervisor phía Electron với atomic lock, session descriptor, PID/health validation và stale recovery.
- Chuyển token từ per-window process sang per-Core session, nhưng chỉ chia sẻ qua descriptor giới hạn quyền trong user scope.
- Thêm client registration, heartbeat, detach và grace-period shutdown.
- Thêm global resource scheduler để serialize workload ML nặng của Docling/OCR.
- Namespace storage/history theo product và viết migration idempotent từ userData Mark Tini hiện có.
- Kiểm tra launch race, Core crash, renderer crash và đóng app theo mọi thứ tự.

## File-Level Plan

- `frontend/electron/coreSupervisor.ts`: quản lý suite root, migration dữ liệu, atomic startup lock, session descriptor, backend detached, client lease/heartbeat, health/token validation, stale recovery và last-client shutdown.
- `frontend/electron/main.ts`: khởi tạo supervisor trước BrowserWindow, truyền Core token qua preload argument và giao lifecycle shutdown cho supervisor; bỏ backend ownership per-product.
- `frontend/electron/preload.ts`: giữ bridge token read-only; không expose session descriptor/token ngoài contract hiện có.
- `frontend/src/services/api.ts`: tiếp tục dùng loopback API/token hiện có; chỉ bổ sung type/status nếu Core diagnostics cần.
- `backend/src/services/resource_scheduler.py`: cung cấp một process-wide re-entrant heavy-job slot và snapshot phục vụ test.
- `backend/src/services/docling_service.py`: dùng global heavy-job slot thay cho lock riêng ở conversion boundary.
- `backend/src/main.py` và `backend/src/services/pdf_to_word_service.py`: serialize PDF-to-Word qua cùng scheduler; health giữ token boundary.
- `backend/src/config.py`, `job_service.py`, `history_service.py`: chỉ thay đổi khi cần để nhận shared data path/migration invariant, không tự di chuyển dữ liệu trong backend.
- `backend/tests/`: test scheduler mutual exclusion và API security không hồi quy.
- `frontend/e2e/`: test concurrent launch dùng cùng Core PID/session, đóng owner trước vẫn giữ product còn lại hoạt động và Core dừng sau client cuối.

## Best-Practice Checklist

- Descriptor/lock/lease chỉ ở đường dẫn suite đã chuẩn hóa; mọi file delete là file cụ thể, không recursive cleanup.
- Session descriptor chỉ được chấp nhận sau token-authenticated health check; PID/file tồn tại không đủ.
- Startup race dùng exclusive create (`wx`) và timeout hữu hạn; stale lock cần PID lẫn health verification.
- Backend chạy detached/hidden, không giữ stdio pipe khiến app owner phải sống.
- Migration copy-if-missing, idempotent, không xóa legacy data và không overwrite file đích đã tồn tại.
- Last-client shutdown xác minh lease còn sống trước khi taskkill đúng Core PID.
- Không log token hoặc nội dung descriptor nhạy cảm.

## Verification

```powershell
python -m pytest backend/tests
npm --prefix frontend run lint
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

Expected: backend security/scheduler tests pass; Electron tests chứng minh một Core cho hai product, owner-independent lifecycle và no orphan.

## Acceptance

- Launch đồng thời nhiều product chỉ tạo một backend listener/process.
- Token/origin boundary vẫn chặn request không tin cậy.
- Không chạy đồng thời hai heavy job theo cấu hình mặc định.
- Core thoát trong tối đa 45 giây sau client cuối; stale descriptor không chặn lần mở sau.
- Migration chạy lặp lại không mất hoặc nhân đôi history Mark Tini.
